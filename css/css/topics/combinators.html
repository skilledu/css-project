CSS Combinators

A combinator is something that explains the relationship between the selectors. A CSS selector can contain more than one simple selector. Between the simple selectors, we can include a combinator.

Descendant Combinator (space)

The descendant combinator matches all elements that are descendants of a specified element.

CSS
div p {
   background-color: yellow;
}

Child Combinator (>)

The child combinator selects all elements that are the children of a specified element.

CSS
div > p {
   background-color: yellow;
}

Adjacent Sibling Combinator (+)

The adjacent sibling combinator is used to select an element that is directly after another specific element. Sibling elements must have the same parent element.

CSS
h1 + p {
   background-color: yellow;
}

General Sibling Combinator (~)

The general sibling combinator selects all elements that are next siblings of a specified element.

CSS
h1 ~ p {
   background-color: yellow;
}

Combinators Summary

SymbolNameWhat it Selects
(space)Descendant combinatorAll elements that are inside the specified element.
>Child combinatorAll elements that are direct children of the specified element.
+Adjacent sibling combinatorThe element that is placed immediately after the specified element.
~General sibling combinatorAll elements that are placed after the specified element on the same DOM level.

Practical Examples

A realistic dropdown menu scenario utilizing child (>) and adjacent sibling (+) combinators to prevent styling bleed into nested sub-menus:

CSS
<style>
/* Direct Child Combinator: Only styles the top-level list items */
.nav-menu > li {
   display: inline-block;
   margin-right: 20px;
}

/* Adjacent Sibling: Adds a border between adjacent menu items */
.nav-menu > li + li {
   border-left: 1px solid #ccc;
   padding-left: 20px;
}
</style>

<div class="card">
  <h2>Combinators</h2>
  <p>Adjacent sibling paragraph.</p>
  <p>General sibling paragraph.</p>
  <div>
    <p>Descendant, but not direct child.</p>
  </div>
</div>

Common Mistakes

  • Confusing Descendant (space) with Child (>) − Using a space selects ALL descendants (even grandchildren). Using > selects ONLY direct children. Confusing them causes unintended styling on deeply nested elements.
  • Over-nesting descendant combinators − Writing .main .sidebar .widget ul li a. This creates fragile CSS that breaks if the HTML structure changes slightly, and makes it incredibly hard to override later.
  • Misunderstanding Sibling Combinators − The + combinator only selects the sibling IMMEDIATELY following the first element. If there is a <br> tag between them, the selector fails.

Best Practices

  • Prefer the Child Combinator (>) − Whenever possible, use > instead of a space. It strictly scopes your styles to direct children and prevents "style leaking" into nested components.
  • Limit Combinator Depth − A strict rule of thumb is never to exceed a depth of 3 combinators (e.g., .card > .body > h2). If you go deeper, you should probably just add a new class to the target element.
  • Use Adjacent Siblings for Spacing − The * + * selector (known as the lobotomized owl) is highly effective for adding top-margins only between adjacent sibling elements in a stack.
  • Keep selectors shallow − Overly complex or deeply nested selector chains can slow down CSS matching on large pages. Simpler selectors perform better.

Interview Questions

Q: What is the exact difference between div p and div > p?

A: div p (descendant) selects all <p> tags that exist anywhere inside the div, no matter how deeply nested. div > p (child) selects only <p> tags that are direct children of the div.

Q: How does the adjacent sibling combinator + work?

A: It selects an element that is placed immediately after a specified element, provided they share the same parent (e.g., h1 + p targets only the very first paragraph directly after an h1).

Q: What does the general sibling combinator ~ do?

A: It selects ALL sibling elements that follow the specified element on the same level, not just the immediately adjacent one.

Q: Why might deeply nested descendant combinators cause performance issues?

A: Browsers read CSS selectors from right-to-left. For .container div span a, the browser first finds all a tags on the page, then checks if they have a span parent, then a div grandparent, etc., which is computationally expensive.

Q: Write a selector to target a <ul> that immediately follows an element with the class .header.

A: .header + ul

Summary

Combinators define the relationship between multiple simple selectors. By mastering the descendant (space), child (>), adjacent sibling (+), and general sibling (~) combinators, you can precisely target elements based on their exact location in the DOM tree without needing to clutter your HTML with excessive classes.
