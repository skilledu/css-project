Topic 48

Validations

Validation is the process of checking something against a rule. When you are a beginner, it is very common that you will commit many mistakes in writing your CSS rules. How will you make sure whatever you have written is 100% accurate and up to the W3 quality standards?

If you use CSS, your code needs to be correct. Improper code may cause unexpected results in how your page looks or functions.

If you want to validate your CSS style sheet embedded in an HTML document, you should first check that the HTML you use is valid.

You can use the following tools to check the validity of your CSS:

  • W3C CSS Validator (World Wide Web Consortium): This validator checks your CSS by either file upload, direct input, or using URI. This validator helps you to locate all the errors in your CSS.
  • The WDG CSS Check Validator: Lets you validate your CSS by direct input, file upload, and using URI. Errors will be listed by line and column numbers if you have any. Errors usually come with links to explain the reason of error.
  • A CSS validator checks your Cascading Style Sheets to make sure that they comply with the CSS standards set by the W3 Consortium. There are a few validators which will also tell you which CSS features are supported by which browsers since not all browsers are equal in their CSS implementation.

Why Validate Your HTML Code?

There are a number of reasons why you should validate your code. But major ones are −

  • It helps cross-browser, cross-platform, and future compatibility.
  • A good quality website increases search engine visibility.
  • Professionalism: As a web developer, your code should not raise errors while seen by the visitors.
  • Accessibility Foundation: Valid, well-structured markup is a crucial foundation for accessibility tools like screen readers to parse and interpret your page correctly.

Practical Examples

Example of form validation states.

HTML/CSS
<!DOCTYPE html>
<html>
   <head>
      <style>
         input:invalid {
            border: 2px solid red;
         }
         input:valid {
            border: 2px solid green;
         }
      </style>
   </head>
   <body>
      <h1>Form Validation CSS</h1>
      <p>Enter an email address:</p>
      <input type="email" value="invalid-email">
      <br><br>
      <input type="email" value="valid@email.com">
   </body>
</html>

Validation Workflow

A real-world workflow for validating your CSS:

  • Go to the official W3C CSS Validator (jigsaw.w3.org/css-validator).
  • Upload your styles.css file or paste your code.
  • Review the output: Errors (in red) mean your CSS has syntax flaws and might break. Warnings (in yellow) usually indicate vendor prefixes or deprecated properties.

Common Mistakes

  • Ignoring warnings completely − While you don't always have to fix every warning (e.g., experimental vendor prefixes often trigger warnings), ignoring them completely can lead to keeping deprecated, slow CSS properties in your codebase.
  • Relying only on IDE linting − VS Code will catch a missing semicolon, but it might not know that a specific combination of properties (like trying to set a margin on a table row) is technically invalid CSS according to W3C specs.

Best Practices

  • Automate your validation − In modern professional environments, use tools like Stylelint in your build pipeline. It validates your CSS automatically every time you save, ensuring errors never reach production.
  • Validate before major deployments − If your layout is acting strangely in an older browser, run it through the W3C validator. It often points out a simple typo that the browser silently failed on.

Interview Questions

Q: Why is it important to validate your CSS?

A: Browsers are notoriously forgiving; they will silently ignore broken CSS rules without crashing the page. Validation helps you find these hidden errors, ensuring your site renders identically across different browsers and devices.

Q: What is the official tool used to validate CSS?

A: The W3C (World Wide Web Consortium) CSS Validator.

Q: Does a valid CSS file guarantee your website will look correct?

A: No. Validation only checks syntax and specification compliance. It cannot check if your design is visually appealing, accessible, or functionally what you intended to build.

Summary

CSS Validation is a crucial quality assurance step. Because web browsers hide CSS errors rather than crashing, developers can easily accumulate broken rules. Integrating validation tools like Stylelint into your workflow ensures your stylesheets remain clean, performant, and cross-browser compatible.
