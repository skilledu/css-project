CSS Inheritance

Inheritance in CSS controls what happens when no value is specified for a property on an element. Some CSS properties inherit by default, while others do not.

Inherited vs Non-Inherited Properties

Inherited properties: When no value for an inherited property has been specified on an element, the element gets the computed value of that property on its parent element. Examples include typography properties like color and font-family.

Non-inherited properties: When no value for a non-inherited property has been specified on an element, the element gets the initial value of that property (as specified in the property's summary). Examples include layout properties like margin and border.

Inheritance Keywords

CSS provides four special universal property values for controlling inheritance:

CSS
/* Forces a property to inherit its value from its parent */
.child { color: inherit; }

/* Sets a property to its initial (default) value */
.box { border: initial; }

/* Acts as inherit for inherited properties, and initial for non-inherited ones */
.text { font-weight: unset; }

/* Reverts the cascaded value to the user agent's default style */
.element { display: revert; }

Practical Examples

A practical example showing how to force form elements (which normally reject inherited typography) to inherit the font stack of the body:

CSS
<style>
body {
   font-family: 'Helvetica', sans-serif;
   color: #333;
}

/* Form elements do NOT inherit fonts by default. We must force it: */
button, input, textarea {
   font-family: inherit;
   color: inherit;
}
</style>

Common Mistakes

  • Assuming layout properties inherit − Beginners often wonder why a child div doesn't inherit the border or padding of its parent. Layout properties are explicitly non-inherited.
  • Forgetting about User Agent defaults − Assuming <a> tags will inherit text color from the body. Browsers apply a default blue color to links, which overrides inheritance. You must explicitly set a { color: inherit; } if you want it to blend in.
  • Using inherit blindly − Setting width: inherit on everything can cause layout chaos. It's better to let block elements naturally fill space (auto) rather than forcing inheritance.

Best Practices

  • Rely on natural inheritance for Typography − Set your font-family, line-height, and primary color on the body or :root element and let it cascade down naturally.
  • Use currentColor for SVG icons − If you want an SVG icon to inherit the text color of its parent button, set its fill to fill: currentColor;, which relies on inheritance.
  • Use unset to clear complex properties − If you need to strip all styling off a custom component, using unset is safer than guessing whether a property was originally inherited or not.

Interview Questions

Q: What is the difference between an inherited property and a non-inherited property?

A: Inherited properties (like color and font-size) automatically pass down to child elements. Non-inherited properties (like margin and border) do not pass down and reset to their initial values.

Q: What does the inherit keyword do?

A: It forces a property that normally wouldn't inherit (like a border) to explicitly take the computed value of its parent element.

Q: What is the difference between initial and inherit?

A: initial sets the property to the browser's default CSS specification value (e.g., black for color). inherit sets it to whatever value the parent has.

Q: What does the unset keyword do?

A: It acts as a hybrid: if the property is naturally inheritable, it acts like inherit. If it is naturally non-inheritable, it acts like initial.

Q: Why don't input fields inherit the body's font family automatically?

A: Because browsers apply a User Agent stylesheet that explicitly sets font properties on form elements (like inputs and buttons), which overrides the natural inheritance cascade.

Summary

Inheritance is what makes CSS "cascading." Typography properties naturally flow down the DOM tree, while layout properties stay contained to their specific boxes. By mastering the inherit, initial, and unset keywords, you can control exactly how styles pass from parents to children, saving you from writing repetitive code.
