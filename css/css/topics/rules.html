Topic 47

@ Rules

This chapter will cover the following important @ rules −

Rule Description
@import Imports another style sheet into the current style sheet.
@charset Indicates the character set the style sheet uses.
@font-face Used to exhaustively describe a font face for use in a document.
!important Indicates that a user-defined rule should take precedence over the author's style sheets.

NOTE − There are other @ rules which we will cover in subsequent chapters.

import rule

The @import rule allows you to import styles from another style sheet. It should appear right at the start of the style sheet before any of the rules, and its value is a URL.

It can be written in one of the two following ways −

CSS 
/*
@import "mystyle.css";
or
@import url("mystyle.css");
.......other CSS rules .....
*/

The significance of the @import rule is that it allows you to develop your style sheets with a modular approach. You can create various style sheets and then include them wherever you need them.

charset Rule

If you are writing your document using a character set other than ASCII or ISO-8859-1 you might want to set the @charset rule at the top of your style sheet to indicate what character set the style sheet is written in.

The @charset rule must be written right at the beginning of the style sheet without even a space before it. The value is held in quotes and should be one of the standard character-sets. For example −

CSS 
@charset "iso-8859-1";
/* .......other CSS rules ..... */

font-face Rule

The @font-face rule is used to exhaustively describe a font face for use in a document. @font-face may also be used to define the location of a font for download, although this may run into implementation-specific limits.

In general, @font-face is extremely complicated, and its use is not recommended for any except those who are experts in font metrics.

Example

CSS 
@font-face {
    font-family: "Scarborough Light";
    src: url("http://www.font.site/s/scarbo-lt");
}
@font-face {
    font-family: Santiago;
    src: local("Santiago"), url("http://www.font.site/s/santiago.tt") format("truetype");
    unicode-range: U+??,U+100-220;
    font-size: all;
    font-family: sans-serif;
}

!important Rule

Cascading Style Sheets cascade. It means that the styles are applied in the same order as they are read by the browser. The first style is applied and then the second and so on.

The !important rule provides a way to make your CSS cascade. It also includes the rules that are to be applied always. A rule having an !important property will always be applied, no matter where that rule appears in the CSS document.

For example, in the following style sheet, the paragraph text will be black, even though the first style property applied is red:

CSS 
p { color: #ff0000; }
p { color: #000000; }

So, if you wanted to make sure that a property always applied, you would add the !important property to the tag. So, to make the paragraph text always red, you should write it as follows −

HTML/CSS 
<!DOCTYPE html>
<html>
   <head>
      <style type="text/css">
         p { color: #ff0000 !important; }
         p { color: #000000; }
      </style>
   </head>
   <body>
      <p>Hello World</p>
   </body>
</html>

Here you have made p { color: #ff0000 !important; } mandatory. Now this rule will always apply, even if you have defined another rule like p { color: #000000; }.

CSS FILTERS - TEXT AND IMAGE EFFECTS

You can use CSS filters to add special visual effects — like blurring, adjusting brightness/contrast, or shifting colors — to images and other elements on a webpage, without needing extra image files. The standard CSS filter property (part of the CSS Filter Effects Module) lets you apply these effects directly in CSS, and it is supported in all modern browsers.

blur()

Applies a Gaussian blur to the input image.

CSS 
img {
    filter: blur(5px);
}

brightness()

Applies a linear multiplier to input image, making it appear more or less bright.

CSS 
img {
    filter: brightness(150%);
}

contrast()

Adjusts the contrast of the input.

CSS 
img {
    filter: contrast(200%);
}

drop-shadow()

Applies a drop shadow effect to the input image.

CSS 
img {
    filter: drop-shadow(4px 4px 10px rgba(0,0,0,0.5));
}

grayscale()

Converts the input image to grayscale.

CSS 
img {
    filter: grayscale(100%);
}

hue-rotate()

Applies a hue rotation on the input image.

CSS 
img {
    filter: hue-rotate(90deg);
}

invert()

Inverts the samples in the input image.

CSS 
img {
    filter: invert(100%);
}

opacity()

Applies transparency to the samples in the input image.

CSS 
img {
    filter: opacity(50%);
}

saturate()

Saturates the input image.

CSS 
img {
    filter: saturate(200%);
}

sepia()

Converts the input image to sepia.

CSS 
img {
    filter: sepia(100%);
}

Multiple Filters

You can combine multiple filter functions in one declaration by separating them with a space.

CSS 
img {
    filter: contrast(150%) brightness(1.1);
}

Practical Examples

Defining a custom font face and creating a smooth, infinite rotating animation using CSS rules:

CSS
<style>
/* 1. The @font-face rule imports a custom font */
@font-face {
   font-family: "MyCustomFont";
   src: url("fonts/my-font.woff2") format("woff2");
}

/* 2. The @keyframes rule defines the animation logic */
@keyframes spin {
   from { transform: rotate(0deg); }
   to   { transform: rotate(360deg); }
}

.loading-spinner {
   animation: spin 2s linear infinite;
}
</style>

<div class="loading-spinner" style="width:50px; height:50px; border:5px solid #ccc; border-top-color:blue; border-radius:50%;"></div>

Common Mistakes

  • Overusing @import − Using @import inside a CSS file to load other CSS files forces the browser to download them sequentially (one after the other), crippling page load speed. Too many @import statements block rendering much more than a single combined stylesheet.
  • Placing @charset incorrectly − If you use the @charset "UTF-8"; rule, it MUST be the very first character of the CSS file. If there is a space or comment before it, it fails.
  • Not providing fallback formats in @font-face − Only providing a .ttf file. Modern development requires optimized formats like .woff2 for fast loading.

Best Practices

  • Link CSS in HTML, don't @import − Always use multiple <link rel="stylesheet"> tags in your HTML <head> so the browser can download stylesheets in parallel. Too many @import statements block rendering much more than a single combined stylesheet.
  • Use @keyframes for UI interactions − CSS animations are hardware-accelerated. Prefer them over JavaScript-based animations for simple spinners, loaders, and hover effects.

Interview Questions

Q: Why is @import considered bad practice for web performance?

A: Because it blocks parallel downloading. The browser must download, parse, and execute the main CSS file before it even discovers the @import rule, delaying the download of the secondary stylesheet.

Q: What does the @font-face rule do?

A: It allows developers to provide custom typography by instructing the browser to download a font file hosted on the server, rather than relying on fonts installed on the user's local machine.

Q: What is the difference between a CSS property and an @-rule?

A: A property applies styles directly to an element (e.g., color: red). An @-rule (at-rule) dictates broad behavioral instructions to the CSS parser itself, such as importing files, defining animations, or setting media queries.

Summary

At-rules (@) give CSS its programmatic power. They dictate how the browser parses the file (@charset), bring in external assets (@font-face), and define complex motion paths (@keyframes). Understanding these rules unlocks the advanced, dynamic capabilities of modern CSS.
