Syntax

A CSS comprises of style rules that are interpreted by the browser and then applied to the corresponding elements in your document. A style rule is made of three parts −

TermDescription
SelectorA selector is an HTML tag at which a style will be applied. This could be any tag like <h1> or <table> etc.
PropertyA property is a type of attribute of HTML tag. Put simply, all the HTML attributes are converted into CSS properties. They could be color, border etc.
ValueValues are assigned to properties. For example, the color property can have a value like red or #F1F1F1 etc.

You can put a CSS Style Rule Syntax as follows − selector { property: value } Example: You can define a table border as follows −

CSS
table { border: 1px solid #C00; }

Here table is a selector and border is a property and the given value 1px solid #C00 is the value of that property.

You can define selectors in various simple ways based on your comfort. Let me put these selectors one by one.

Practical Examples

A practical, complete CSS rule demonstrating the syntax structure (Selector, Property, and Value) used to style a realistic UI component like an alert box:

CSS
<style>
/* Selector */
.alert-box {
   /* Property : Value ; */
   background-color: #f8d7da;
   color: #721c24;
   padding: 15px;
   border-radius: 4px;
   border: 1px solid #f5c6cb;
}
</style>

Common Mistakes

  • Forgetting the trailing semicolon − Missing the semicolon at the end of a declaration causes the browser to ignore the current property AND the next property, breaking the layout silently.
  • Missing curly braces − Forgetting to close a } will cause all subsequent CSS rules in the file to break.
  • Using an equals sign instead of a colon − Writing color = red; instead of color: red; is a common syntax error for developers coming from JavaScript.
  • Typos in property names − Writing backgroud-color instead of background-color. Browsers silently ignore invalid properties, making typos hard to debug.

Best Practices

  • One Declaration Per Line − Always place each property-value pair on its own line. It makes the CSS vastly easier to read and allows version control systems (like Git) to track changes cleanly.
  • Consistent Indentation − Indent the declarations inside the curly braces (usually by 2 or 4 spaces) to clearly separate the selector from the properties.
  • Always include the last semicolon − Even though the semicolon on the very last property inside a block is technically optional in CSS, you should always include it to prevent errors when adding new properties later.
  • Use Comments for Structure − Use CSS comments /* ... */ to group related rules together in large stylesheets.

Interview Questions

Q: What are the three main components of a CSS rule?

A: The Selector (which elements to style), the Property (what aspect to style), and the Value (the specific style to apply).

Q: What is a CSS Declaration?

A: A declaration is a single property and its value, separated by a colon and ended with a semicolon (e.g., color: blue;).

Q: What happens if a browser encounters a CSS property or value it doesn't understand?

A: The browser will completely ignore that specific declaration and gracefully continue parsing the rest of the CSS rules.

Q: Is white-space significant in CSS syntax?

A: Generally no. You can use spaces, tabs, and newlines freely to format your CSS for readability without affecting how it works.

Q: How do you write a comment in CSS?

A: CSS comments start with /* and end with */. They can span multiple lines.

Summary

The syntax of CSS is simple but strict. Every rule consists of a selector pointing to an HTML element, followed by a declaration block enclosed in curly braces {}. Inside the block, declarations are written as property: value; pairs. Maintaining consistent formatting, avoiding typos, and remembering semicolons are crucial habits for writing maintainable CSS.
