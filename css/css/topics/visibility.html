Topic 14

Visibility

A property called visibility allows you to hide an element from view. You can use this property along with JavaScript to create very complex menu and webpage layouts.

NOTE: Remember that the source code will still contain whatever is in the invisible element, so you should not use this to hide sensitive information such as credit card details or passwords.

ValueDescription
visibleThe box and its contents are shown to the user (default).
hiddenThe box and its content are made invisible, although they still affect the layout of the page.
collapseThis is for use only with dynamic table columns and row effects.

Example

HTML/CSS 
<!DOCTYPE html>
<html>
   <body>
      <p>This paragraph is visible in normal way.</p>
      <p style="visibility:hidden;">This paragraph is hidden (still takes space).</p>
      <p>This paragraph is also visible.</p>
   </body>
</html>

Practical Examples

Fading out an element while keeping its physical space intact, ensuring the layout below it doesn't jump:

CSS
<style>
.hidden-element {
   /* Visually hidden, but still takes up space */
   visibility: hidden;
   opacity: 0;
   transition: visibility 0s 0.3s, opacity 0.3s linear;
}

.hidden-element.active {
   visibility: visible;
   opacity: 1;
   transition: opacity 0.3s linear;
}
</style>

<div class="hidden-element active" style="padding:20px; background:blue; color:white;">I fade out smoothly! (Remove the 'active' class via JS)</div>

Common Mistakes

  • Confusing visibility with display − display: none removes the element entirely, causing surrounding text to collapse and fill the space. visibility: hidden leaves an empty "hole" exactly the size of the element. This difference matters for accessibility: content hidden with visibility: hidden can still confuse screen reader users in some cases, and may remain in the tab order in certain browsers.
  • Trying to transition visibility alone − You cannot smoothly animate visibility (it snaps instantly from hidden to visible). You must pair it with opacity to get a smooth fade effect.
  • Assuming hidden elements can be clicked − A visibility: hidden element cannot be clicked, whereas an opacity: 0 element (without hidden visibility) CAN still be clicked!

Best Practices

  • Use visibility for UI states − It is perfect for hiding validation error messages beneath form inputs before the user types anything, preserving the form's height so it doesn't jump around.
  • Combine with Opacity for animations − Always toggle both opacity and visibility together when fading out interactive elements (like modals) to ensure they look good AND block unwanted clicks.

Interview Questions

Q: What is the main difference between visibility: hidden and display: none?

A: display: none completely removes the element from the document flow, meaning it takes up zero physical space. visibility: hidden makes the element invisible, but it still occupies its exact original dimensions in the layout.

Q: What does visibility: collapse do?

A: It is specifically designed for table rows (<tr>) or columns. It acts exactly like display: none for those elements (collapsing the row), but acts like visibility: hidden on standard elements.

Q: Will screen readers announce text inside a visibility: hidden element?

A: No. Screen readers ignore both display: none and visibility: hidden content.

Summary

The visibility property is a subtle but vital layout tool. It allows you to hide elements while preserving the structural integrity of your grid or page flow. Mastering its relationship with opacity and display is crucial for building smooth, non-jumping UI animations.
