Topic 46

Layers

CSS gives you the opportunity to create layers of various divisions. The CSS layers refer to applying the z-index property to elements that overlap with each other.

The z-index property is used along with the position property to create an effect of layers. You can specify which element should come on top and which element should come at the bottom.

A z-index property can help you to create more complex webpage layouts. The following is an example which shows how to create layers in CSS:

HTML/CSS 
<!DOCTYPE html>
<html>
   <body>
      <div style="background-color:red;
         width:300px;
         height:100px;
         position:relative;
         top:10px;
         left:80px;
         z-index:2">
      </div>
      <div style="background-color:yellow;
         width:300px;
         height:100px;
         position:relative;
         top:-60px;
         left:35px;
         z-index:1;">
      </div>
      <div style="background-color:green;
         width:300px;
         height:100px;
         position:relative;
         top:-220px;
         left:120px;
         z-index:3;">
      </div>
   </body>
</html>

Practical Examples

A well-structured z-index hierarchy ensuring a modal overlay always appears above a fixed header navigation:

CSS
<style>
.header-nav {
   position: fixed;
   z-index: 100; /* Stays above normal scrolling content */
}

.modal-overlay {
   position: fixed;
   z-index: 1000; /* Must be higher than the header */
}
</style>

<div style="position:relative; height:150px;">
  <div class="header-nav" style="top:0; left:0; width:100%; background:black; color:white; padding:10px;">Nav (z-index 100)</div>
  <div class="modal-overlay" style="top:50px; left:50px; width:200px; background:rgba(0,0,0,0.8); color:white; padding:20px;">Modal (z-index 1000)</div>
</div>

Common Mistakes

  • Applying z-index to static elements − z-index ONLY works if the element has a position property of relative, absolute, fixed, or sticky. Applying it to a static (default) element does absolutely nothing.
  • Z-index Wars (99999) − Frustrated developers often slap z-index: 99999 on an element when it isn't showing up. This makes future layering conflicts impossible to debug.
  • Misunderstanding Stacking Contexts − If a parent element has z-index: 10, its child can have z-index: 9999, but it will NEVER appear above an outside element with z-index: 11. The parent traps the child in a local context.

Best Practices

  • Establish a Global Z-Index Scale − Use a sensible scale in your project (e.g., 10 for dropdowns, 100 for sticky headers, 1000 for modals/tooltips) to maintain order.
  • Create new stacking contexts carefully − Be aware that properties like opacity (less than 1) and transform automatically generate a new local stacking context, which can cause unexpected layering bugs.

Interview Questions

Q: Why is my z-index not working?

A: The two most common reasons are: 1) The element does not have a position property applied (it is still static). 2) The element is trapped inside a parent's lower Stacking Context.

Q: What is a Stacking Context?

A: It is a local 3D layering system created by certain CSS properties (like positioned elements with z-index, opacity, or transforms). Child elements are layered relative to this local context, and their z-index values cannot break out above the parent's layer.

Q: If two elements overlap and neither has a z-index, which one appears on top?

A: The one that is defined last in the HTML source code will appear on top.

Summary

Z-index provides 3D depth to 2D web pages. While applying a z-index is simple, mastering it requires a deep understanding of Stacking Contexts—knowing that layering is not global, but rather grouped by parent containers. Keep your z-index numbers sensible and always remember to apply positioning!
