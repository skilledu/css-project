Topic 37

Layouts

Hope you are very comfortable with HTML tables and you are efficient in designing page layouts using HTML Tables. But you know CSS also provides plenty of controls for positioning elements in a document. Since CSS is the wave of the future, why not learn and use CSS instead of tables for page layout purposes?

The following list collects a few pros and cons of both the technologies −

Aspect Tables CSS
Browser Support Most browsers support tables CSS support is being slowly adopted
Responsiveness More forgiving when browser window size changes - morphing content and wrapping to accommodate changes accordingly CSS positioning tends to be exact and fairly inflexible
Ease of Learning Much easier to learn and manipulate CSS rules can be more complex

But each of these arguments can be reversed −

Aspect Description
Future Support CSS is pivotal to the future of Web documents and will be supported by most browsers
Precision CSS is more exact than tables, allowing your document to be viewed as you intended, regardless of the browser window
Organization Keeping track of nested tables can be a real pain. CSS rules tend to be well organized, easily read, and easily changed

Finally, we would suggest you to use whichever technology makes sense to you and use what you know or what presents your documents in the best way.

CSS also provides table-layout property to make your tables load much faster. Following is an example −

HTML/CSS
<table style="table-layout:fixed;width:600px;">
  <tr>
    <td width="150">CSS table layout cell 1</td>
    <td width="200">CSS table layout cell 2</td>
    <td width="250">CSS table layout cell 3</td>
  </tr>
</table>

You will notice the benefits more on large tables. With traditional HTML, the browser had to calculate every cell before finally rendering the table. When you set the table-layout algorithm to fixed, however, it only needs to look at the first row before rendering the whole table. It means your table will need to have fixed column widths and row heights.

Sample Column Layout

Here are the steps to create a simple Column Layout using CSS −

Set the margin and padding of the complete document as follows −

CSS 
body {
   margin:9px 9px 0 9px;
   padding:0;
   background:#FFF;
}

Now, we will define a column with yellow color and later, we will attach this rule to a <div>:

CSS 
#level0 {
   background:#FC0;
}

Upto this point, we will have a document with yellow body, so let us now define another division inside level0 −

CSS 
#level1 {
   margin-left:143px;
   padding-left:9px;
   background:#FFF;
}

Now, we will nest one more division inside level1, and we will change just background color −

CSS 
#level2 {
   background:#FFF3AC;
}

Finally, we will use the same technique, nest a level3 division inside level2 to get the visual layout for the right column −

CSS 
#level3 {
   margin-right:143px;
   padding-right:9px;
   background:#FFF;
}
#main {
   background:#CCC;
}

Complete the source code as follows −

HTML/CSS 
<!DOCTYPE html>
<html>
   <head>
      <style>
         body {
   margin:9px 9px 0 9px;
   padding:0;
   background:#FFF;
}
#level0 {background:#FC0;}
#level1 {
   margin-left:143px;
   padding-left:9px;
   background:#FFF;
}
#level2 {background:#FFF3AC;}
#level3 {
   margin-right:143px;
   padding-right:9px;
   background:#FFF;
}
#main {background:#CCC;}
</style>
   </head>
   <body>
      <div id="level0">
         <div id="level1">
            <div id="level2">
               <div id="level3">
                  <div id="main">
                     Final Content goes here...
                  </div>
               </div>
            </div>
         </div>
      </div>
   </body>
</html>

Similarly, you can add a top navigation bar or an ad bar at the top of the page.

Practical Examples

A masonry-style newspaper layout that flows text gracefully across multiple columns while preventing awkward breaks inside paragraphs:

CSS
<style>
.newspaper-article {
   /* Creates responsive columns that won't get thinner than 250px */
   column-width: 250px;
   column-gap: 30px;
   column-rule: 1px solid #ccc; /* Draws a line between columns */
}

.newspaper-article p {
   /* Prevents a single paragraph from being split across two columns */
   break-inside: avoid;
   margin-bottom: 1rem;
}
</style>

<div class="newspaper-article">
  <p>First paragraph of news. This is a very interesting story.</p>
  <p>Second paragraph of news. CSS Layouts are awesome.</p>
  <p>Third paragraph of news. Multi-column makes it easy.</p>
</div>

Common Mistakes

  • Using CSS Columns for structural grids − Trying to build a dashboard layout with column-count. CSS Columns flow content top-to-bottom first, then over to the next column. If you want content to read left-to-right (row-by-row), you must use CSS Grid instead.
  • Hardcoding column-count: 4 − Forcing 4 columns looks great on desktop but creates illegibly thin columns on mobile. Always use column-width instead so the browser can reduce the column count automatically on small screens.
  • Setting fixed heights − Setting a fixed height on the multi-column container prevents the columns from balancing their content evenly.

Best Practices

  • Use column-width for intrinsic responsiveness − Declaring a width (e.g., 300px) tells the browser "give me as many columns as will fit, but never thinner than 300px." This eliminates the need for media queries!
  • Utilize break-inside: avoid − Always apply this to child elements (like blockquotes, images, or cards) inside the column layout to prevent them from being awkwardly sliced in half at the bottom of a column.

Interview Questions

Q: What is the main difference between column-count and column-width?

A: column-count forces an exact number of columns regardless of the screen size, which can break on mobile. column-width defines an ideal minimum width, allowing the browser to calculate how many columns can fit, making it inherently responsive.

Q: How do you make an element span across all columns (like a large headline in an article)?

A: By applying column-span: all; to that specific element.

Q: In what direction does content flow inside a CSS Multi-column layout?

A: Vertically (top-to-bottom) filling the first column entirely before spilling over into the next column.

Summary

The CSS Multi-column layout module is highly specialized. While it is terrible for building overall page structures (leave that to Flexbox and Grid), it is absolutely unmatched for flowing text-heavy content like newspaper articles, or building pure-CSS masonry image galleries using break-inside: avoid.
