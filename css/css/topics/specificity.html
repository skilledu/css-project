CSS Specificity

CSS Specificity is the set of rules that browsers use to decide which CSS styles should be applied to an HTML element when there are multiple conflicting rules.

Imagine you have multiple CSS rules trying to change the color of the same text. One rule says the text should be red, and another says it should be blue. The browser needs a way to decide which rule wins. Specificity is the scoring system that makes this decision.

Simple Example

Let us look at a very simple example where two rules target the same element.

HTML/CSS 
<!DOCTYPE html>
<html>
<head>
  <style>
    p {
      color: blue;
    }
    .text-red {
      color: red;
    }
  </style>
</head>
<body>
  <p class="text-red">This text will be red.</p>
</body>
</html>

In this example, the class selector .text-red wins over the element selector p, so the text becomes red. We will learn exactly why this happens as we explore the priority rules.

CSS Specificity Priority

To understand which CSS rule wins, you must know the basic priority order. From strongest to weakest, the order is:

Inline Style > ID > Class / Attribute / Pseudo-class > Element / Pseudo-element

Let us look at each level of this priority system separately.

Inline Styles

An inline style is written directly inside an HTML tag using the style attribute.

HTML 
<h1 style="color: purple;">This is a heading</h1>

Inline styles have the highest priority. They will override almost any style written inside a CSS file because they are attached directly to the specific element.

ID Selectors

An ID selector uses the id attribute of an HTML element to target it. In CSS, an ID is selected using the hash (#) symbol.

CSS 
#main-title {
  color: green;
}

An ID is meant to be unique on a webpage, meaning it targets only one specific element. Because of this, it has a very high specificity and will always beat class and element selectors.

Class, Attribute, and Pseudo-class Selectors

These selectors have medium priority. They are stronger than basic element selectors but weaker than IDs.

  • Class selectors: Target elements with a specific class, starting with a dot (like .button).
  • Attribute selectors: Target elements based on their HTML attributes (like [type="text"]).
  • Pseudo-classes: Target elements in a specific state (like :hover or :focus).
CSS 
.highlight { color: yellow; } /* Class */
input[type="text"] { border: 1px solid black; } /* Attribute */
a:hover { color: orange; } /* Pseudo-class */

Element and Pseudo-element Selectors

These are the weakest selectors in CSS.

  • Element selectors: Target generic HTML tags directly (like p, div, or h1).
  • Pseudo-elements: Target specific parts of an element (like ::before or ::after).
CSS 
p { color: gray; } /* Element */
p::first-letter { font-size: 24px; } /* Pseudo-element */

Specificity Score

Now that you understand the basic priority, let us introduce the numerical scoring system behind it. Every CSS selector is given a score in four categories. This is often written as four numbers separated by commas: 0,0,0,0.

  • Inline Style gives a score of 1,0,0,0.
  • ID gives a score of 0,1,0,0.
  • Class, Attribute, or Pseudo-class gives a score of 0,0,1,0.
  • Element or Pseudo-element gives a score of 0,0,0,1.

You can think of these numbers simply as thousands, hundreds, tens, and ones to easily see which score is larger.

How to Calculate Specificity

To calculate the total specificity score of a CSS rule, you just count how many of each type of selector it contains.

  • .button (One class) = 0,0,1,0
  • .nav .menu-item (Two classes) = 0,0,2,0
  • #header .logo (One ID, one class) = 0,1,1,0
  • div p a (Three elements) = 0,0,0,3

Important Specificity Rule

When comparing scores, the browser checks the highest-priority category first (from left to right). A higher priority category will always win, no matter how many lower priority selectors you combine.

For example, a score of 0,1,0,0 (one ID) will easily beat a score of 0,0,5,0 (five classes). This is because the ID category is stronger than the Class category.

Same Specificity

What happens if two rules have the exact same specificity score? The rule that is written later in your CSS code will win. This is the "Cascading" behavior of CSS.

CSS 
.text {
    color: blue;
}

.text {
    color: red;
}

Since both selectors are identical classes, they have the exact same score. The text will be red because the red rule is written later.

The !important Rule

The !important rule is a special CSS keyword that overrides all normal specificity rules.

CSS 
p {
    color: red !important;
}

Even if another rule has a very high specificity (like an ID or an inline style), the rule with !important will still win. However, it should not be used as a quick fix for every CSS problem. Excessive use of !important makes your CSS very difficult to maintain and debug because it breaks the natural cascading rules.

Practical Examples

Element vs Class

A class selector has a higher specificity (0,0,1,0) than an element selector (0,0,0,1). The text will be blue.

CSS 
p { color: red; } /* 0,0,0,1 */
.highlight { color: blue; } /* 0,0,1,0 (Wins) */

Class vs ID

An ID selector has a higher specificity (0,1,0,0) than a class selector (0,0,1,0). The text will be green.

CSS 
.highlight { color: blue; } /* 0,0,1,0 */
#unique-text { color: green; } /* 0,1,0,0 (Wins) */

Multiple Classes vs ID

Even if you combine multiple classes, they cannot beat a single ID. The ID category is fundamentally stronger. The text will be purple.

CSS 
.box .inner .text { color: orange; } /* 0,0,3,0 */
#main-box { color: purple; } /* 0,1,0,0 (Wins) */

Same Specificity

When two rules have the exact same specificity, the one written last in the CSS file will win. The text will be orange.

CSS 
.message { color: yellow; }
.message { color: orange; } /* Written later (Wins) */

Inline Style vs ID

An inline style (1,0,0,0) will always override an ID (0,1,0,0). The text will be pink.

HTML/CSS 
<style>
  #title { color: black; } /* 0,1,0,0 */
</style>

<h1 id="title" style="color: pink;">Hello World</h1> <!-- 1,0,0,0 (Wins) -->

Common Mistakes

  • Using !important everywhere: Beginners often use !important when their CSS is not working. This is a bad habit that makes future styling changes incredibly difficult.
  • Using unnecessary IDs for styling: Avoid styling with IDs unless absolutely necessary. Classes are much easier to override and reuse across your project.
  • Writing overly complicated selectors: A selector like div ul li a.active span is too specific and hard to manage. A simple class like .nav-link-active is much better.
  • Not checking specificity: When a CSS rule is not applying as expected, it is almost always because another rule has a higher specificity score.
  • Assuming length equals strength: A very long selector containing many elements (like 10 elements) will still lose to a single simple class selector, because classes are in a higher priority category.

Best Practices

  • Prefer simple class selectors: Build your styles primarily around classes (like .card, .btn, .header). This keeps specificity low and predictable.
  • Keep specificity low: It is much easier to manage a website where all CSS rules have relatively low specificity scores.
  • Use IDs for JavaScript or HTML anchors: Use IDs for identifying elements in JavaScript or creating page anchors, rather than for general CSS styling.
  • Use !important only when genuinely needed: Reserve !important for absolute exceptions, such as overriding a third-party library's styling that you cannot change otherwise.

Interview Questions

Q: What is CSS Specificity?

A: It is the set of rules browsers use to determine which CSS styles should be applied to an element when multiple conflicting rules target the same element.

Q: Why is CSS Specificity important?

A: It ensures that browsers know exactly how to resolve styling conflicts, allowing developers to predictably override and manage styles in large applications.

Q: What is the specificity priority order?

A: Inline Style > ID > Class / Attribute / Pseudo-class > Element / Pseudo-element.

Q: Which is stronger: a class or an ID?

A: An ID is always stronger than a class.

Q: Which wins: .nav ul li a or #navbar a?

A: #navbar a wins because it contains an ID selector, which automatically beats any number of classes and elements.

Q: What happens when two selectors have the exact same specificity?

A: The rule that appears later in the CSS document will win.

Q: What is !important?

A: It is a special keyword added to a CSS declaration that overrides all normal specificity rules, including inline styles.

Q: Is a longer CSS selector always more specific?

A: No. A short selector with an ID (#header) will always beat a very long selector that only contains elements and classes.

Q: Why should unnecessary IDs be avoided for styling?

A: IDs have extremely high specificity, making them very difficult to override later if you need to reuse or slightly change a component's design.

Summary

CSS Specificity acts as a scoring system to resolve styling conflicts. The fundamental rule you must remember is the priority order:

Inline Style > ID > Class / Attribute / Pseudo-class > Element / Pseudo-element

When two rules have the exact same specificity, the later rule wins. By keeping your selectors simple and prioritizing classes over IDs, you will write cleaner, more maintainable CSS code that rarely requires the use of !important.
